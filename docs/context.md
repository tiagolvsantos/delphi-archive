# Delphi Archive — Context

> Generated from docs/context/ on 2026-11-12 — do not edit directly; run /context-refresh primer.

*The central, read-mostly archive for investment research and quantitative studies produced across the Cerberus ecosystem.*

## What it is

`delphi-archive` is a data archive, not an application. It has no code to run, no build, and no tests — it is a structured collection of PDF reports and research studies, version-controlled in git, intended as the durable historical record of research output.

## What it does

- Stores **per-ticker equity research PDFs** under `stock_reports/`, named `report_<TICKER>_<TIMESTAMP>.pdf`, with about 765 ticker folders across US large-caps, international ADRs, crypto-adjacent equities, biotech, shipping, cannabis, and more.
- Stores **quantitative research studies** under `studies/`, about 140 PDFs organized by domain: `alternative_data/`, `credit/`, `crypto/`, `fundamentals/`, `liquidity/`, `macro/` (the largest), `market_internals/`, `options/`, `sentiment/`, `space/`, `stats/`, `technical-reports/`, `volatility/`.

## Purpose / why it exists

Research generated by `cerberus_workbench` (stock reports, study PDFs) needs a durable, append-friendly home separate from the tool that generates it — so historical reports remain stable and browsable even as the generating pipeline evolves, and so the research corpus itself can be versioned and reviewed independently of application code.

## Ecosystem & relationships

- **Populated one-way by `cerberus_workbench`**: `scripts/sync_delphi_archive.py` (`task sync`) in Workbench copies the latest PDF for each stock report and study from its own `outputs/` into this repository and deletes older PDFs in each destination folder. The same script can target a Box folder instead (`task sync:box`). This archive never pushes anything back — it is a pure sink.
- Not connected to `cerberus_data`, `cerberus_indicators`, `cerberus_terminal`, `cerberus_trader`, or `stock_research`.

## Architecture

```
delphi-archive/
├── stock_reports/   # Per-ticker equity research PDFs, generated by Cerberus Workbench
└── studies/         # Quantitative research studies, organized by domain
```

There is no runtime architecture to describe beyond this directory layout — it is a flat content archive.

## Key concepts & terminology

- **`report_<TICKER>_<TIMESTAMP>.pdf`** — the fixed naming convention for stock reports; reports are never renamed by hand.
- **Domain folders under `studies/`** — the fixed taxonomy new studies are filed into; a new top-level domain folder is only added when a study genuinely fits none of the existing ones.

## Notable design decisions / current state

- **Latest-wins per folder, history in git** — each sync replaces a ticker's or study's PDF with the newest one and deletes older PDFs, so the working tree holds the current research and git history holds every earlier version. Nothing is deleted or renamed by hand.
- **No independent logic** — anything describing *how* a report or study was produced belongs in `cerberus_workbench`'s documentation, not here; this repo only describes what is stored and how it's organized.
